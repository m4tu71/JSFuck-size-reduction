# JSFuck size reduction

**Python encoder version:** `0.1.0.dev6` (development; first stable release planned as `0.1.0`).

Experimental Python JSFuck encoder that measures output character count against the
reference encoder at [jsfuck.com](https://jsfuck.com/).

## Setup

Python 3.10+ (no runtime dependencies). Node.js is used to execute semantic tests.
The benchmark downloads a pinned copy of the official JSFuck 0.5.0 source from `aemkei/jsfuck` (not the outdated npm release). To run:

```sh
python -m unittest discover -s tests -v
python -m jsfuck_py.benchmark
python -m jsfuck_py.benchmark --version
```

For your own input set, pass a JSON array of strings using `--cases cases.json`.
Use `--output results.json` to persist length comparisons.

## API

```python
from jsfuck_py.encoder import encode

expression = encode('console.log(1)', optimize=True, wrap=False)
code = encode('console.log(1)', wrap=True)
```

`wrap=False` produces a JS expression that evaluates to the source string;
`wrap=True` executes it. Use identical settings for both encoder comparisons.

The Python implementation uses mappings derived from the upstream
[aemkei/jsfuck](https://github.com/aemkei/jsfuck) JSFuck 0.5.0 encoder.
It expands the official symbol recipes and uses dynamic programming to choose
between individual-character encodings and built-in multi-character literals.

**Limitations:** This is not a globally optimal JSFuck encoder. The initial
search does not yet share common subexpressions or exhaustively optimize string
escape loaders. Unicode and execution semantics are tested using Node.js. Benchmark
numbers are computed locally; no performance claims are assumed in advance.

## Current baseline results

Against the pinned JSFuck 0.5.0 reference, in plain-string mode:

| Input | Reference | Python | Reduction |
| --- | ---: | ---: | ---: |
| `0` | 8 | 6 | 25.0% |
| `1` | 10 | 8 | 20.0% |
| `01` | 13 | 11 | 15.38% |
| `1234567890` | 249 | 247 | 0.80% |
| `hello` | 1034 | 1034 | 0.0% |
| `Hello world!` | 4514 | 4514 | 0.0% |

These are measured samples, not claims of global optimality. To compare execution-mode
overhead, run `python -m jsfuck_py.benchmark --wrap`.

The cached backslash expression in `jsfuck_py/backslash_jsfuck_050.b64`
is generated by the pinned upstream JSFuck encoder; it is not an alternate
JavaScript implementation of this project's encoder.

## Native method character search (experimental)

The Python encoder now tests alternative character-extraction expressions
from the string form of native Array methods, starting with `[]["at"]`.
It evaluates `at`, `flat`, `fill`, `find`, `map`, `filter`, `join`,
`sort` and `entries`, using `false`, `true`, `NaN` and other cheap
prefixes to shift character indices. Index expressions are selected
by emitted character count. Only strictly shorter alternatives replace
a mapping, and all compiled character mappings are semantically tested
under Node.js.

Pinned JSFuck 0.5.0 comparison, string mode (GitHub Actions, Node.js 22):

| Input | Official | Python | Reduction |
| --- | ---: | ---: | ---: |
| `native` | 1,022 | 162 | 84.15% |
| `function add(a,b){return a+b}` | 1,602 | 1,442 | 9.99% |
| `function function` | 504 | 503 | 0.20% |
| `at` | 30 | 30 | 0% |

**Portability note:** native function source text is implementation-dependent.
Like the upstream encoder, these recipes assume the tested native
function string format. Test on additional JavaScript engines before
claiming cross-engine compatibility.

## Versioning and releases

The Python encoder uses Semantic Versioning, with PEP 440 development suffixes.
The single authoritative version lives in `jsfuck_py/_version.py` and is
exposed as `jsfuck_py.__version__`. Packaging metadata reads it automatically.
The reference JSFuck 0.5.0 release is a *separate version*.

To prepare a release after tests pass:

1. Update `jsfuck_py/_version.py` from `0.1.0.dev6` to `0.1.0`
   (or the next planned version), and update `CHANGELOG.md`.
2. Merge the reviewed PR; create an annotated Git tag `v0.1.0` pointing
   at the merged release commit, then publish its GitHub release.
3. Start the next development cycle with a new `.dev0` version.

Do **not** create release tags from a development branch.

The benchmark `--output results.json` includes the Python encoder version,
reference commit SHA, comparison mode and per-input results for reproducibility.

## Native suffix optimization

The Python encoder explores low-cost single-argument `slice(start)` expressions
for suffixes of native Array-method strings. Use the following commands to
separate input-specific savings from general-source performance:

```sh
python -m jsfuck_py.benchmark --cases benchmarks/javascript_samples.json
python -m benchmarks.ablation
python -m benchmarks.ablation --cases benchmarks/native_suffix_cases.json
```

The suffix optimization alone did not reduce output on the 20-source JavaScript
sample; see `docs/optimization-research.md` for the controlled ablation.

## Typed literal optimizations

Typed dynamic programming tracks when addition is guaranteed to concatenate
strings. It shortens primitive substrings without changing JavaScript values;
operator-heavy ambiguous cases use a conservative fallback.

```sh
python -m benchmarks.typed_ablation
python -m benchmarks.typed_ablation --cases benchmarks/typed_primitive_cases.json
```

## Repeated-character search (experimental)

The Python encoder now evaluates `String.prototype.repeat` for long runs of
individual characters. It includes the complete method-call cost, so runs of
cheap characters may remain unchanged. Example: 32 `x` characters shrink
from 29,855 to 1,988 JSFuck characters in the pinned comparison.

```sh
python -m benchmarks.repetition_ablation
python -m benchmarks.repetition_ablation --cases benchmarks/javascript_samples.json
python -m jsfuck_py.benchmark --cases benchmarks/repetition_cases.json
```

These are intentionally selected inputs, not estimates of typical savings.

## Numeric-code Unicode batching

For sufficiently long expensive strings, the Python encoder now evaluates
`String.fromCharCode` and `String.fromCodePoint` using a JSFuck-only
`split / reduce / apply / bind` invocation path. It compares both candidates
against the older escape-decoder path and returns the shortest valid result.

```sh
python -m jsfuck_py.benchmark --cases benchmarks/long_unicode_cases.json
python -m benchmarks.numeric_batch_ablation
python -m benchmarks.numeric_batch_ablation --cases benchmarks/numeric_batch_cases.json
```

Batched code points generally have high fixed costs. Small inputs may be
unchanged; see the research document for measured crossover examples.

## Experimental shared-substring reuse

The new `share_substrings` option is **off by default**. When enabled,
the Python encoder can generate a private function that accepts a repeated
string fragment as an argument and reuses it to construct the original
JavaScript source string. It never injects declarations into the source.

```python
from jsfuck_py import encode

ordinary = encode("const x=1;" * 6)
shared = encode(
    "const x=1;" * 6,
    share_substrings=True,
    avoid_source_identifiers=True,
)
```

Only select the helper when the **complete** resulting JSFuck expression is
shorter than the existing encoder output. Variable-name candidates are
evaluated for total encoded output cost; the optional source-name exclusion
is conservative because the helper has an isolated scope.

```sh
python -m benchmarks.shared_substring_ablation
```

The helper creates a dynamic function at runtime, which may increase execution
time or fail in environments that block `Function` via CSP.
